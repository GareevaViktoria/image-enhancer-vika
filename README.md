# Проявитель — ИИ-коррекция изображений в браузере

Учебный проект: система улучшения изображений (яркость, контрастность, цветность)
с ML-моделью, работающей **полностью в браузере пользователя**. Без сервера.

## Что внутри и как это отвечает ТЗ

| Требование ТЗ | Как выполнено |
|---|---|
| ML-модель в браузере | Нейросеть на **TensorFlow.js** (`js/model.js`) анализирует превью и подбирает параметры коррекции |
| Яркость / контраст / цветность | Применяются WebGL-шейдером на GPU (`js/worker.js`), fallback на CPU |
| Работа во всех браузерах | Нативные API + WebGL с откатом на Canvas 2D |
| Асинхронный режим | Вся обработка в **Web Worker**, UI не блокируется |
| Форматы JPG, PNG, HEIC, BMP | Нативный декодер + `heic2any` для HEIC |
| До 15 Мпк, ≤30 с | Модель работает на уменьшенном превью, коррекция — на GPU |
| Объём ≤ 10 МБ | Свой код + heic2any (1.3 МБ); TF.js грузится с CDN |

## API модуля (по ТЗ)

Класс `ImageEnhancer` (`js/api.js`) реализует контракт:

- `submitTask(file)` → `taskId` — постановка задачи
- `getStatus(taskId)` → `{status, progress}` — статус задачи
- `cancelTask(taskId)` → `{success}` — прерывание
- `getResult(taskId)` → `{blob, params}` — готовое изображение
- событие `statusChange` `{taskId, status, progress}` — изменение статуса

## Как запустить локально

Из-за ES-модулей и Web Worker нельзя просто открыть `index.html` двойным
кликом — нужен локальный сервер. Любой из вариантов:

```bash
# Python (есть почти везде)
python3 -m http.server 8000

# или Node
npx serve
```

Затем откройте `http://localhost:8000` в браузере.


## Алгоритм коррекции

Модель не сдвигает яркость линейно (такой подход «стягивает» снимок к серому
и портит удачные кадры), а подбирает параметры полноценного тонального
пайплайна. Каждый снимок проходит четыре стадии:

1. **Автоуровни по перцентилям.** Точки чёрного и белого берутся по 0.4 и 99.6
   перцентилю поканально — тональный диапазон раскрывается на полную.
   Поканальность заодно смягчает цветовой сдвиг (жёлтый или синий налёт).
   Доля общей точки адаптивна: у насыщенных кадров уровни делаются почти
   общими, чтобы не добавлять кислотности.
2. **Гамма** — светлота средних тонов. Есть коридор нормы (медиана 0.40–0.62):
   если снимок уже хорошо проэкспонирован, гамма равна 1.0 и яркость не
   трогается. Осветление блокируется при выбитых светах, затемнение — при
   провалах в чёрное.
3. **S-образная кривая контраста** — добавляет объём, не выбивая света и тени,
   в отличие от линейного контраста.
4. **Vibrance** — цветность. При подъёме щадит уже насыщенные пиксели (кожа и
   небо не уходят в кислоту), при снижении работает в полную силу.

## Гарантия улучшения каждого снимка

Требование ТЗ — любое фото должно меняться в лучшую сторону. Поэтому параметры
не просто вычисляются формулой, а проходят замкнутый контур проверки:

1. Нейросеть даёт отправную точку.
2. Коррекция применяется к превью, и по результату считаются объективные
   метрики: охват тонального диапазона, экспозиция, контраст, цветность и
   сохранность деталей в светах и тенях (штраф за клиппинг).
3. Перебираются 48 вариантов вокруг базового; выбирается тот, что даёт
   максимальный прирост суммарной оценки качества.
4. Действует порог заметности: если ни один вариант не даёт различимого
   изменения, полировка усиливается, пока изменение не станет видимым —
   но только если качество при этом не падает.

Оценка «до» и «после» показывается пользователю в интерфейсе, поэтому
улучшение измеримо, а не «на глаз». Подбор занимает около 80 мс.

Результаты на эталонных типах кадров (оценка из 100):

| Кадр | Качество | Заметность |
|---|---|---|
| яркий удачный | 75 → 86 | 0.065 |
| тёмный | 20 → 46 | 0.141 |
| блёклый плоский | 33 → 42 | 0.061 |
| перенасыщенный | 42 → 47 | 0.046 |
| пересвет | 1 → 18 | 0.077 |
| обычный средний | 66 → 87 | 0.083 |
| почти идеальный | 80 → 80 | 0.032 |
| сине-холодный | 65 → 70 | 0.086 |

Ни один кадр не остаётся без прироста качества и без заметного изменения.

Три параметра (гамма, сила S-кривой, vibrance) подбирает нейросеть; уровни
считает вспомогательный алгоритм. Итог: улучшается любой снимок — тусклый
осветляется, плоский получает объём, блёклый — цвет, а уже удачный яркий кадр
сохраняет светлоту и выигрывает за счёт раскрытия диапазона.

## Как это работает по шагам


1. Пользователь бросает файл → `submitTask` декодирует его в `ImageBitmap`.
2. Bitmap передаётся в Worker (без копирования, через transferable).
3. Worker строит превью 160 px, считает поканальные гистограммы, перцентили и
   24 признака.
4. ML-модель предсказывает гамму, силу S-кривой и vibrance.
5. WebGL-шейдер применяет уровни, гамму, S-кривую и vibrance к полному
   изображению на GPU.
6. Результат отдаётся как Blob, показывается слайдер «до/после», кнопка скачивания.

Прогресс на каждом шаге транслируется через событие `statusChange`.
